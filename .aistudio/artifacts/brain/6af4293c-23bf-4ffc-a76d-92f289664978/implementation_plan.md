# แผนการพัฒนา: ระบบตรวจสอบสต็อกขณะอนุมัติใบเบิก และการนับมูลค่าตามวันที่ Admin อนุมัติจริง

## 1. วัตถุประสงค์และภาพรวม
1. **การตรวจสอบสต็อกขณะ Admin อนุมัติใบเบิก (Stockcard Check):**
   - เมื่อ Admin กดอนุมัติหรือระบุจำนวนจ่าย หากรายการใดมีจำนวนคงเหลือใน Stockcard ไม่พอจ่าย (คงเหลือน้อยกว่าที่ขอ) หรือคงเหลือเป็น `0`
   - ระบบจะเปิดหน้าต่างแจ้งเตือนและให้ Admin เลือกแนวทางจัดการ:
     - **ทางเลือกที่ 1: "ต้องการรับของเข้าระบบก่อนไหม"** -> มีปุ่มทางลัดไปยังหน้ารับของเข้าคลัง (Goods Received Notes) หรือบันทึกรับเข้า เพื่อให้มีสต็อกพร้อมจ่าย
     - **ทางเลือกที่ 2: "ปรับจ่ายเท่าที่มี"** -> ระบบจะปรับจำนวนอนุมัติเท่ากับสต็อกคงเหลือจริง และให้เลือกการจัดการสำหรับส่วนที่เหลือ (Remainder):
       - **ยืม (Loan):** บันทึกจำนวนที่เหลือเป็นรายการยืมของหน่วยงาน
       - **ค้างจ่าย (Backorder):** บันทึกจำนวนที่เหลือเป็นรายการค้างจ่ายรอของเข้า
       - **ยกเลิก (Cancel Remainder):** ตัดยอดเหลือเฉพาะที่จ่ายจริง ยกเลิกส่วนที่ขาด
       - **ไม่อนุมัติ (Reject Remainder):** ระบุไม่อนุมัติในส่วนที่เหลือหรือไม่จ่าย
2. **การยึดถือวันที่ Admin อนุมัติ (Approval Date) ในการเก็บข้อมูลและคำนวณมูลค่า:**
   - บันทึกคอลัมน์ `approved_at` ลงฐานข้อมูล ณ วันและเวลาที่ Admin ทำการอนุมัติจริง
   - ปรับการคำนวณในรายงานทุกส่วน (เช่น รายงานสรุปการใช้เวชภัณฑ์, รายงานเปรียบเทียบแผนจัดซื้อ, รายงานประจำเดือน) ให้ยึด `approvedAt` เป็นหลัก
   - หากหน่วยงานส่งใบเบิกในเดือนก่อนหน้า (เช่น ส่งเบิกปลายเดือนกันยายน) แต่อธิการ/Admin อนุมัติในเดือนปัจจุบัน (เช่น ตุลาคม) มูลค่าและรายการตัดจ่ายจะถูกนับเป็นของ **เดือนปัจจุบัน** อย่างถูกต้องตรงตามความเป็นจริง

## 2. ขั้นตอนการดำเนินงาน

### ขั้นตอนที่ 1: ปรับปรุงการตรวจสอบสต็อกและการเลือกตัวเลือกในหน้าอนุมัติ (`components/PickingView.tsx` & `components/AdminDashboard.tsx`)
1. ในหน้าจัดของ/อนุมัติใบเบิก แสดงแถบคอลัมน์ **"สต็อกคงเหลือในคลัง"** เทียบกับ **"จำนวนที่ขอเบิก"** ชัดเจน พร้อมไฮไลต์สีเตือนเมื่อสต็อกไม่พอหรือเป็น 0
2. เมื่อ Admin กด "ยืนยันการอนุมัติ" หรือ "อนุมัติตามที่ขอ":
   - ระบบจะตรวจเช็กเทียบกับ `inventoryMap`
   - หากมีรายการที่สต็อกไม่พอจ่าย (`approvedQuantity > currentStock` หรือ `currentStock <= 0`):
     - เปิด Modal ให้ Admin เลือกระหว่าง:
       1. **รับของเข้าระบบก่อน:** สวิตช์ไปยังแท็บ "รับเวชภัณฑ์เข้าคลัง" พร้อมจดจำสถานะใบเบิก
       2. **ปรับจ่ายเท่าที่มี และจัดการส่วนที่เหลือ:**
          - สำหรับแต่ละรายการที่ไม่พอ สามารถคลิกเลือกตัวเลือกว่าส่วนที่ขาดจะปรับเป็น **ยืม / ค้างจ่าย / ยกเลิก / ไม่อนุมัติ**
          - มีปุ่ม "นำไปใช้กับทุกรายการที่ไม่พอ" เพื่อความสะดวกรวดเร็ว
3. ทำการแยกรายการเบิกจ่ายจริง และสร้างรายการ ยืม / ค้างจ่าย ตามที่ Admin ระบุ

### ขั้นตอนที่ 2: แก้ไขการบันทึกและประมวลผลวันที่อนุมัติ (`services/supabaseService.ts`)
1. แก้ไขฟังก์ชัน `saveSimpleApproval` และ `updateProcessedRequisitionItems`:
   - บันทึก `approved_at: new Date().toISOString()` ลงในตาราง `requisitions`
2. ปรับปรุงการโหลดข้อมูลใบเบิก (`getRequisitions`, `getRequisitionsForDepartment`):
   - อ่าน `approvedAt` จาก `r.approved_at` เป็นหลัก (แทนที่จะ fallback ไปใช้ `submitted_at` ซึ่งเป็นวันส่งของหน่วยงาน)
3. ตรวจสอบให้แน่ใจว่าระบบบันทึกประวัติการเบิกจ่ายและ Stock Card เชื่อมโยงกับ Transaction Date ณ วันที่อนุมัติ

### ขั้นตอนที่ 3: ปรับปรุงการแสดงผลรายงานและมูลค่าตามเดือนที่อนุมัติ (`components/ReportsView.tsx` & `components/admin/SummaryView.tsx`)
1. ปรับเกณฑ์คัดกรองวันที่ของใบเบิกใน `ReportsView.tsx`:
   - รายงานการเบิกจ่าย, รายงานสรุปการเบิกเทียบแผนจัดซื้อ, รายงานการใช้วัสดุรายเดือน:
   - ยึด `req.approvedAt` เป็นอันดับแรก หากมี `approvedAt` ให้นับเดือนและปีตามวันที่ Admin อนุมัติเท่านั้น
   - หากยังไม่อนุมัติ จะไม่ถูกดึงมาคิดมูลค่าเบิกจริง
2. ตรวจสอบรายงานเปรียบเทียบแผนจัดซื้อ (Purchase Plan Comparison):
   - รวมยอดเบิกจริงและยืมที่ Admin อนุมัติในเดือนนั้น ๆ อย่างครบถ้วน

### ขั้นตอนที่ 4: การทดสอบและตรวจสอบความถูกต้อง
1. ทดสอบสร้างใบเบิกที่ของในคลังมีไม่พอหรือเป็น 0
2. ตรวจสอบการแจ้งเตือน Modal:
   - ทดสอบตัวเลือก "รับของเข้าก่อน"
   - ทดสอบตัวเลือก "ปรับจ่ายเท่าที่มี" -> แยกเป็น ยืม, ค้างจ่าย, ยกเลิก, ไม่อนุมัติ
3. ทดสอบการบันทึกวันที่ `approved_at` และตรวจสอบผลในหน้ารายงานประจำเดือน
4. รัน `compile_applet` เพื่อตรวจสอบความสมบูรณ์ของโค้ด
